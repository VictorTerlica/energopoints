# ЭнергоТочки 3.0 — РП, ТП и ПС по координатам

Локальное Android-приложение на Kotlin + Jetpack Compose (Material 3) для учёта
энергетических объектов (РП, ТП и ПС): поиск, добавление, редактирование,
удаление, личные заметки, геолокация и открытие точки в картографическом
приложении.

Приложение **не отправляет данные автоматически**. Файл `points.json` хранится
локально, импорт/экспорт выполняются через системный файловый диалог (SAF).
Координаты передаются картографическому приложению только по нажатию
«Показать на карте».

---

## Возможности

- Список точек в порядке из JSON (без сортировки), поиск по номеру/названию.
- Фильтры: район и тип РП / ТП / ПС.
- Карточки с цветной градиентной иконкой, районом, типом, бейджем
  принадлежности (РОССЕТИ — зелёный, ССК — синий) и личной заметкой.
- Экран деталей в `ModalBottomSheet`: JSON-примечание, координаты,
  личная заметка, кнопка «Показать на карте».
- Меню «Три точки» на главном экране:
  - «Добавить точку»;
  - «Импорт из папки Download» (SAF `OpenDocument`);
  - «Экспорт в папку Download» (SAF `CreateDocument`).
- Меню «Три точки» на экране деталей:
  - «Редактировать»;
  - «Удалить» с подтверждением.
- Редактирование всех полей: `code`, `type`, `name`, `district`, `latitude`,
  `longitude`, `note`, `ownership`, `iconColor`.
- Кнопка «Уточнить по GPS» (`Icons.Default.MyLocation`) с runtime-разрешением
  `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`.
- Палитра из 6 цветов иконки. Для ПС по умолчанию используется фиолетовый.
- Информационная проверка: пустые поля, диапазоны координат, дубликаты
  `code + district + type + name`. Ничего не блокирует: маленький чип
  «Замечания: N» + Snackbar с кнопкой «Показать»; список открывается по нажатию.
- Дубликатом считается только полное совпадение кода, района, типа и названия.
  Одинаковый номер с другим названием — не дубликат.
- Если в форме оставить пустую/нечисловую координату, сохраняется `0.0`
  и появляется информационное замечание.
- Снэкбары: «Точка добавлена», «Изменения сохранены», «Точка удалена»,
  «Импортировано точек: N», «Файл сохранён» и т.д.
- Светлая/тёмная тема, фирменные цвета `#1565C0` / `#FFA000`, скругления 12–16 dp.
- Перед каждой перезаписью `points.json` создаётся резервная копия
  `points.json.bak`.

## Приватность и безопасность

> **Главное правило: реальный `points.json` не должен попасть в git, на GitHub
> или в APK.**

- В репозитории только `app/src/main/assets/points.example.json` — пример на
  4 обезличенные точки (РП, ТП и ПС).
- Реальный `points.json` и `points.json.bak` игнорируются `.gitignore`.
- Приложение читает/пишет приватную внешнюю папку:
  `Android/data/com.energypoints.finder/files/`.
- На Android 11+ ОС ограничивает прямой доступ к `Android/data`, поэтому
  используйте импорт через системный диалог: доступ даётся только к выбранному
  файлу, разрешения на хранилище не нужны.
- Геолокация запрашивается только при нажатии «Уточнить по GPS».
- Нет аналитики, рекламы и сетевых запросов к вашим серверам.
- `INTERNET` нужен только для открытия неявного `geo:`-интента во внешнем
  картографическом приложении.
- Резервное копирование приложения отключено (`android:allowBackup="false"`).
- Не публикуйте APK, собранный с встроенным `assets/points.json`: файл окажется
  внутри APK. Веб-загрузка GitHub не учитывает `.gitignore` — проверяйте вручную.

## Быстрый старт через GitHub (без Android Studio)

### 1. Подготовьте проект

1. Распакуйте архив.
2. Не добавляйте свой `points.json` в проект — для сборки он не нужен.

### 2. Загрузите проект на GitHub

1. GitHub → **New repository**. Рекомендуется **Private**.
2. **Add file → Upload files**.
3. Перетащите всё содержимое папки, включая скрытые `.github`, `.gitignore`,
   `.gitattributes`, `gradlew` и папку `gradle`.
4. Убедитесь, что `.github/workflows/build-apk.yml` на месте.
5. Commit в ветку `main`.

> Веб-загрузка не учитывает `.gitignore`. Не перетаскивайте `points.json`,
> `local.properties`, `build/`, `.gradle/`, APK и ключи подписи.

### 3. Запустите сборку

- Автоматически при push в `main`, либо вручную:
  **Actions → Build debug APK → Run workflow**.
- Дождитесь зелёной галочки.

### 4. Скачайте APK

1. Откройте завершённый запуск в **Actions**.
2. В разделе **Artifacts** скачайте `energy-points-debug-apk.zip`.
3. Внутри — `app-debug.apk`. Установите на телефон, разрешив установку из
   неизвестных источников.
4. Артефакт хранится 30 дней.

### 5. Загрузите данные

**Способ А — импорт через приложение (рекомендуется):**

1. Меню ⋮ → **«Импорт из папки Download»**.
2. Если точки уже есть, подтвердите замену. Если внешний `points.json` уже
   существует, его предыдущая версия сохранится в `points.json.bak`.
3. Выберите `points.json` в Downloads/«Документах».
4. Приложение сохранит данные в
   `Android/data/com.energypoints.finder/files/points.json` (импортируются все
   прочитанные точки, даже с замечаниями).
5. Если есть замечания, появится чип «Замечания: N» и Snackbar с кнопкой
   «Показать»; импорт при этом не отменяется.

**Способ Б — USB/MTP (Android 10 и ниже):**

1. Подключите телефон в режиме передачи файлов.
2. Откройте `Android/data/com.energypoints.finder/files/`.
3. Скопируйте `points.json` в UTF-8.
4. Перезапустите приложение (или используйте импорт).

**Способ В — ADB:**

```bash
adb push points.json /sdcard/Android/data/com.energypoints.finder/files/points.json
```

**Способ Г — вручную через приложение:**

Создайте точки кнопкой **«Добавить точку»** и сохраните — приложение само
создаст `points.json` во внешней папке.

Если файла нет, приложение покажет экран с инструкцией и кнопку
**«Посмотреть демо-пример»**. Демо не подставляется автоматически.

## Экспорт в Download

1. Меню ⋮ → **«Экспорт в папку Download»**.
2. Выберите папку и подтвердите имя `points.json`.
3. Приложение запишет JSON через SAF (проверка не блокирует экспорт).
4. Появится снэкбар «Файл сохранён».

Экспорт не изменяет файл во внешней папке приложения.

```json
        "type": "тп",

        "ownership": "РОССЕТИ",
        "iconColor": "#6A1B9A"

    ]
  },
  "Ленинский": {
    "рп": [],

      }

    "пс": []
  }

```

### Поля точки

| Поле | Обязательное | Описание |
|---|---|---|
| `code` | да | Номер/код, например `РП-101`, `ТП-17` или `ПС-5`. |
| `type` | да | `рп`, `тп` или `пс`. |
| `name` | да | Название объекта. |
| `district` | да | Район. При загрузке также берётся ключ верхнего уровня. |
| `latitude` | да | Широта: число от −90 до 90. |
| `longitude` | да | Долгота: число от −180 до 180. |
| `note` | нет | Примечание из файла. |
| `ownership` | нет | `РОССЕТИ`, `ССК` или иное значение. |
| `iconColor` | нет | Один из 6 цветов палитры; иначе цвет по типу. |

Допускаются координаты строкой (`"53.195873"`) и с запятой (`"53,195873"`).

### Проверка данных

- Проверка **информационная** и ничего не блокирует.
- Замечания: пустые поля, координаты вне диапазонов, неизвестный тип,
  дубликаты, нечисловые координаты в JSON.
- Дубликат — полное совпадение `code + district + type + name` (без учёта
  регистра). Одинаковый номер с разным названием дубликатом не считается.
- На экране появляется компактный чип **«Замечания: N»**; по нажатию
  открывается список. Дополнительно показывается Snackbar с кнопкой
  **«Показать»**.
- Импорт сохраняет все прочитанные точки, даже если есть замечания;
  нечисловые/отсутствующие координаты записываются как `0.0` с пояснением.
- Сохранение формы тоже не блокируется: пустые координаты превращаются в
  `0.0` и сопровождаются замечанием. Остальные поля можно сохранить пустыми —
  проверка покажет их в списке.
- При старте файл читается терпимо: проблемные координаты заменяются на `0.0`,
  объекты не теряются.
- Технические ошибки (нечитаемый JSON, нет доступа к файлу) также показываются
  маленьким уведомлением, а не модальным диалогом.

## GPS

1. Откройте форму добавления/редактирования.
2. Нажмите **«Уточнить по GPS»**.
3. Разрешите геолокацию (точную или приблизительную).
4. Координаты подставятся в поля «Широта» и «Долгота».

Используется платформенный `LocationManager` без Play Services. Если GPS
недоступен, приложение попробует Network-провайдер и последнюю известную
локацию. При отказе в разрешении появится снэкбар.

---

## Карты

Одна кнопка **«Показать на карте»** формирует неявный `ACTION_VIEW`:

```text
geo:{latitude},{longitude}?q={latitude},{longitude}({Uri.encode(name)})
```

Откроется приложение карт по умолчанию (Яндекс, Google, 2ГИС и т.д.).
Fallback-ссылок и отдельных кнопок для конкретных приложений нет. Если
обработчик не найден, показывается снэкбар.

## Личные заметки

- Хранятся в DataStore Preferences, только на устройстве.
- Ключ: `note_<район>_<тип>_<код>`.
- При изменении кода/района/типа заметка переносится на новый ключ.
- При удалении точки её заметка удаляется.
- Очистка данных приложения удаляет все заметки.

## Локальная сборка

1. Откройте папку в Android Studio (JDK 17).
2. Дождитесь Gradle Sync: wrapper скачает Gradle 8.4.
3. Сборка из терминала:

```bash
chmod +x gradlew
./gradlew assembleDebug
```

Windows: `gradlew.bat assembleDebug`.

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Для проверки без реального файла откройте демо-пример. Если нужен встроенный
файл, положите `points.json` в `app/src/main/assets/` **локально** и не
коммитьте его.

## Частые проблемы

**«Нужен файл points.json»**

- Используйте «Импорт из папки Download» или «Добавить точку».
- Проверьте путь `Android/data/com.energypoints.finder/files/points.json`.
- Убедитесь, что файл не называется `points.json.txt`.

**Импорт не выполнился**

- Семантические замечания (дубликаты, пустые поля, координаты) импорт
  **не блокируют** — откройте чип «Замечания: N» или кнопку «Показать».
- Если файл не читается (битый JSON/нет доступа), появится Snackbar с
  кнопкой «Показать»; исправьте JSON и повторите импорт.

**GPS не определяет координаты**

- Проверьте разрешение в настройках приложения.
- Включите геолокацию и GPS.
- В помещении GPS может не работать — используется Network/last known.

**Карта не открывается**

- Установите любое картографическое приложение с поддержкой `geo:`.
- Приложение не делает fallback на браузер по требованию ТЗ.

**Экспорт не туда сохранился**

- Системный диалог `CreateDocument` позволяет выбрать папку; по умолчанию
  предлагается `points.json` и последняя папка.

**Сборка в Actions падает**

- Проверьте, что загружены `gradlew`, `gradle/wrapper/gradle-wrapper.jar` и
  `.github/workflows/build-apk.yml`.
- Откройте лог шага **Build debug APK**.
